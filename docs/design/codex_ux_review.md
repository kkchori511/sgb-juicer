# 생기부 착즙기 UX 레이아웃 검토

작성일: 2026-11-07

## 검토 범위와 결론

검토 자료는 [확정 요구사항](../REQUIREMENTS.md), [Claude 1차 레이아웃안](LAYOUT_DRAFT.md), 참고 앱의 [SPEC.md](~/projects/ncloud-pdf-ocr/docs/SPEC.md)와 [index.html](~/projects/ncloud-pdf-ocr/app/web/index.html), [style.css](~/projects/ncloud-pdf-ocr/app/web/style.css), [app.js](~/projects/ncloud-pdf-ocr/app/web/app.js)다. 브라우저나 앱을 실행하지 않은 문서·화면 소스 기반 검토이며, 실제 교사 사용성 테스트 결과는 아니다. 외부 전송 없이 검토했다.

1차안의 현황판 중심 진입, 인박스의 단계 표시, 학생 목록과 기록의 분리는 유지할 만하다. 다만 **명렬 준비 → 자료 연결 → 항목에 누적 → 최종안 채택 → 검토·마감 → 내보내기** 사이의 완료 조건이 빠져 있다. 교사는 메뉴 순서보다 “이 자료가 누구의 어느 항목에 들어갔고, 지금 내보내도 되는가”를 확인할 수 있어야 한다.

우선순위 기준:

- **높음**: 다른 학생·항목에 기록될 가능성, 자료 유실, 개인정보 전송, 다음 작업 불가, 마감·내보내기 오류에 직결한다.
- **중간**: 반복 작업량이나 초보자의 이해·복귀에 큰 영향을 준다.
- **낮음**: 핵심 흐름이 완성된 뒤 편의성과 시각적 완성도를 높인다.

이 문서에서 ‘권고’는 확정 요구사항의 구현 제안이고, ‘결정 필요’는 요구사항만으로 동작을 확정할 수 없는 부분이다. 제안한 저장·재개·되돌리기 등은 기존에 확정된 기능으로 간주하지 않는다.

### 참고 앱에서 가져올 것과 바꿔야 할 것

- **[중간] 유지**: 블루그레이 바탕·흰 입력칸·명확한 기본 버튼, 지침/예시의 좌우 배치, 바이트 표시, 실행 대상 수, 단계별 진행·경과 시간·중지 후 결과 유지. 참고 소스의 `prompt-box`, `toolbar`, `progress`, `openProgress`, `applyResult`가 참고점이다.
- **[높음] 변경**: 참고 앱 `init()`은 CLOVA 키까지 모두 있어야 설정을 벗어나는 구조다. 이 앱은 OpenRouter 키만 처음에 필수이고 CLOVA는 PDF OCR 선택 시에만 요청해야 한다(B2).
- **[높음] 변경**: 참고 명세는 OCR 직후 AI가 학번·이름을 추출하는 방식이다. 이 앱은 앱 내부 규칙 추출과 인적사항 제거가 선행되어야 한다(B3, E2). 참고 앱의 안내 문구도 그대로 재사용하면 안 된다.
- **[높음] 변경**: 참고 앱 `bindStage1()`의 새 PDF 작업은 기존 학생·결과를 지우는 구조다. 이 앱은 여러 묶음·연간 누가기록이므로 새 가져오기가 기존 묶음을 대체해서는 안 된다.
- **[높음] 변경**: 참고 앱의 2안 순환 삭제·선택 해제(`applyResult`)와 미선택 결과를 빈칸으로 저장하는 방식(`save`)을 그대로 쓰면 최종안 관리가 불안정하다. 3개 보관·잠금 규칙에 맞춰 채택본 처리까지 정해야 한다.
- **[중간] 변경**: 참고 앱은 `student-body` 3등분과 창 높이에 맞춘 큰 지침칸(`sizePromptAreas`)을 사용한다. 여기에 좌측 메뉴·명렬을 추가하면 본문 확인이 밀린다. 지침은 접을 수 있는 설정 영역으로 두되, 펼치면 지침과 예시를 함께 보여준다.

## 2. 권장 흐름과 화면별 개선 레이아웃

### 2.1 전체 흐름·공통 틀 — [높음]

```text
처음 한 번: 키 → 역할·학년도·담당 → 명렬 → 현황판
반복 작업: 자료 가져오기 → 매칭 확정 → AI 정제(선택) → 항목에 보내기
                                               ↓
           항목별 누가기록 → 학생별/일괄 종합 → 최종안 채택
                                               ↓
                                  검토·마감 → 항목별 내보내기

직접 기록: 항목별 기록 → 누가기록 추가 ────────────┘(종합으로)
기작성문:  항목별 기록 → 이미 쓴 생기부 넣기 → 다듬기/최종안 채택
```

직접 입력과 기작성문은 인박스를 반드시 통과시키지 않는다(E6, E8). 매칭과 정제는 인박스 내부 단계이고, 마감은 학생×항목의 상태다. 모든 작업을 하나의 긴 마법사에 가두지 않는다.

```text
+-----------------------------------------------------------------------+
| 생기부 착즙기 [v0.1 β]  [2026학년도 v]   이번 작업 / 잔액 N 크레딧     |
+----------------+------------------------------------------------------+
| 현황판         | 현재 위치: 항목별 기록 > 공통수학1 > 20301 김OO       |
| 자료 인박스 (3)| 범위: 2026 · 1학기 · 공통수학1 / 저장됨 15:04        |
| 항목별 기록    |                                                      |
| 일괄 종합      |              선택한 작업의 본문                      |
| 검토·내보내기  |                                                      |
|----------------|                                                      |
| 명렬·담당 관리 |                                                      |
| 태그 관리      |                                                      |
| 성취기준 관리  |                                                      |
| 설정 / 유의사항|                                                      |
+----------------+------------------------------------------------------+
```

- ‘사용 안내’의 상세 콘텐츠는 A5대로 후속 작업으로 둔다. 현재 단계의 짧은 설명·막힌 이유·복구 버튼은 초기 버전에서도 제공한다.
- 담임 전용 항목은 비담임에게 숨긴다. 역할 변경 시 기존 기록을 삭제하지 않고 어떻게 보관할지 결정해야 한다.
- 이전 학년도는 제목 옆에 ‘보관·조회 전용’을 상시 표시하고 입력·정제·이동·마감 변경을 막는다. 조회·내보내기는 허용하는 방향을 권고한다.
- 학년도 변경은 읽기 전용 전환인지 새 학년도 생성인지 구분한다. 처리 중인 작업이 있을 때 전환 처리도 필요하다.
- **[중간] 화면 폭**: 1366×768 및 Windows 확대 125%를 검증 조건으로 제안한다. 작은 창에서는 메뉴·학생 목록을 접고 ‘기록 | 최종안’ 탭으로 바꾼다. 긴 문장은 가로 스크롤 없이 읽히게 한다. 실제 화면 검증은 구현 후 필요하다.

### 2.2 첫 실행 설정 — [높음]

```text
+-----------------------------------------------------------------------+
| 시작 설정   1 연결 → 2 담당 → 3 명렬 → 4 일정·완료                    |
|-----------------------------------------------------------------------|
| OpenRouter API 키 [************************] [표시]                   |
| [가입·키 발급 안내 펼치기]    연결 상태: 확인 전                       |
| AI 모델: 1번 기본 모델 표시  [모델 설정]                               |
| [ ] 학습 차단 (기본 꺼짐)  무료 모델 사용 제한 가능                    |
| 키는 exe 옆 설정 파일에 평문으로 저장됩니다.                          |
| CLOVA OCR 연결: 스캔 PDF를 가져올 때 설정할 수 있습니다.              |
|                                                   [다음: 담당 설정]  |
+-----------------------------------------------------------------------+
| 담당 설정: 학년도 [2026]  역할 (담임 / 비담임)                         |
| 담임반 [2학년 3반]                                                    |
| 과목 [공통수학1 / 1학기] [추가]  동아리 [과학탐구] [추가]             |
| 담임 항목: 연간 / 3학년 담임이면 1학기 말 마감                         |
| [이전]                                             [다음: 명렬 등록] |
+-----------------------------------------------------------------------+
```

4칸 모델 등록·목표 바이트·성취기준·프롬프트를 모두 첫 설정의 필수 입력으로 늘리지 않는다. 기본값을 보여주고 작업 시 조정하게 한다. 일정은 건너뛰어도 현황판에서 ‘일정 추가’를 찾을 수 있게 한다(C6–C8).

명렬 단계에서는 ‘담임반 미등록 / 공통수학1 30명 등록 / 동아리 미등록’처럼 준비 상태를 요약한다. ‘나중에 등록’은 허용하되 완료 화면에 “미등록 대상은 자료 매칭 전에 명렬이 필요합니다”와 바로 가기를 둔다. OpenRouter 키가 없는 경우 설정 진입은 요구사항대로 유지한다. 키 발급 실패 시 오프라인 명렬 준비까지 허용할지는 별도 결정 사항이다.

```text
| 열 연결: 학번 [A열 v] 이름 [B열 v] 학년 [C열 v] 반 [D열 v]             |
| 과목만: 성취수준 [E열 v] / [3단계 | 5단계]                            |
|-----------------------------------------------------------------------|
| 행 | 학번  | 이름 | 학년·반 | 성취수준 | 확인                          |
|  1 | 20301 | 김OO | 2-3     | B        | 기존 학생과 연결              |
|  2 | 20301 | 이OO | 2-3     | A        | ! 학번 중복·이름 불일치       |
|  3 | 30102 | 박OO | 3-1     | -        | 동아리: 1학기 마감 대상       |
|-----------------------------------------------------------------------|
| 정상 28 / 확인 필요 2    [문제 행만 보기]             [명렬 반영]      |
| [비활성 학생 보기]  선택 학생 [비활성화] [다시 활성화]                 |

```

- 학번은 문자열로 취급해 앞자리 0 유실을 피하고, 표시 정렬과 식별 기준을 구분한다. 학번 중복·누락·이름 충돌은 반영 전에 해결하도록 권고한다.
- 한 학생이 학급·여러 과목·동아리에 동시에 소속될 수 있음을 표시한다. 명렬마다 별개 학생으로 복제하지 않는다. 학년도 간 동일 학번 처리 규칙은 별도 결정이 필요하다.
- 동아리는 학생별 학년 정보가 있어야 C5를 적용할 수 있다. 학번 형식만 보고 학년·반을 확정하지 않는다.
- 비활성화 영향(매칭 후보·일괄 보내기·일괄 종합·내보내기 제외)을 실행 전에 설명한다. 소속별 제외인지 학생 전체 비활성화인지는 요구사항 결정 후 표시해야 한다.
- 인박스에서 넘어온 경우 하단에 ‘명렬 반영 후 원래 매칭으로 돌아가기’를 제공한다.

### 2.4 현황판 — [높음]

```text
+-----------------------------------------------------------------------+
| 일정: D-3 자율·진로 12/10(주황) · D-10 세특 12/17 · [+2개] [관리]     |
| 세특 학기 보기 [1학기 | 2학기]  * 담임 항목·동아리는 연간 표시        |
| [2-3 담임반] [공통수학1·1학기] [과학탐구·연간]                       |
| 선택 대상: 2-3 담임반 / 활성 30명  상태는 학생×항목 기준              |
| 다음 할 일: [명렬 등록 1곳] [매칭 대기 2묶음] [최종안 검토 8건]       |
|-----------------------------------------------------------------------|
| 학번  | 이름 | 자율(연간) | 진로(연간) | 행특(연간) | 내 과목·동아리  |
| 20301 | 김OO | 입력 중    | 최종안 있음| 마감       | 수학1 / 탐구    |
| 20302 | 이OO | 기록 없음  | 입력 중    | 입력 중    | 수학1           |
| 범례: 회색 기록 없음 / 노랑 입력 중 / 파랑 최종안 있음 / 초록 마감    |
+-----------------------------------------------------------------------+
| 과목·동아리 카드 선택 시 아래 표로 전환                               |
| 반 [전체 v] 학년 [전체 v] 상태 [전체 v] [확인 필요만]                  |
| 마감 18/30명 [진행 막대] / 비활성 1명 제외                            |
| 학번·이름 | 상태 | 기록 수 | 채택 최종안 바이트 | 확인 사항           |
```

- 빈 명렬이면 빈 표 대신 ‘명렬 등록 → 자료 가져오기’ 순서의 버튼을 보여준다. 기록 없는 학생에게는 ‘자료 가져오기/직접 기록’을 안내한다. 성취기준 생성은 세특에서만 선택 경로로 제공한다.
- 담임 카드의 숫자는 학생 수와 항목 상태 수가 섞이지 않게 한다. 권고: 카드에는 ‘학생 30명 / 마감 54/90항목’, 표에는 학생×항목 상태를 표시한다. 대상별 집계 단위는 확정이 필요하다.
- H5의 공용 칸은 학생이 실제 속한 내 과목·동아리 링크를 담는다. 다른 반 학생을 담임표에 추가하지 않고 과목 카드에서 조회한다.
- **[중간] 다음 할 일**은 명렬 미등록 → 매칭 미완료 → 보내기 대기 → 최종안 검토 → 마감·내보내기 순으로 안내하되, 이미 마친 단계를 반복 권유하지 않는다.
- C7대로 당일 빨강, 7일 이내 주황, 지난 일정은 이 줄에서 제외하고 설정에 회색으로 보관한다. ‘+N개’는 예정 일정 전체를 열며, ‘내일’ 같은 짧은 텍스트도 병기한다.

### 2.5 자료 인박스·가져오기 — [높음]

페이지 나머지 경고만으로는 중간에 백지·누락 페이지가 섞여 학생 경계가 밀리는 문제를 못 찾는다. 매칭 화면에서 각 기록의 원본 페이지 범위를 확인할 수 있게 한다. 페이지 재묶기 기능은 E2를 보완할 추가 요구사항으로 제안한다.

### 2.7 학생 매칭 — [높음]

```text
+-----------------------------------------------------------------------+
| 진로 학습지 / 2-3 학급 → 진로(연간)                                  |
| 1 가져오기 완료 > 2 학생 매칭 > 3 정제 > 4 보내기 검토                 |
| 확정 28 / 확인 필요 2 / 제외 1  [확인 필요만] [명렬 등록·수정]         |
|-----------------------------------------------------------------------|
| 원본 위치 | 규칙 추출값    | 연결할 학생        | 상태                |
| 1~2쪽    | 20301 김OO     | 20301 김OO         | 후보 → [확정]       |
| 3~4쪽    | 학번 없음 이OO | [20302 이OO v]     | 동명이인 확인       |
| 5~6쪽    | 20399 박OO     | [명렬에서 찾기]    | 명렬에 없음         |
|-----------------------------------------------------------------------|
| [원본 이미지/텍스트]      | 선택 행 후보: 학번·이름·학년·반 표시     |
| 추출값 직접 수정 가능     | 이름 유사 후보는 추천이며 확정 아님      |
| [선택 행 제외·이유 입력]  | [확인한 후보 일괄 확정]                   |
| 학번 없음·이름 충돌 2건을 해결해 주세요. [다음: 정제] 비활성          |
+-----------------------------------------------------------------------+
```

- 학번 일치도 이름 충돌을 보여준다. 이름만으로 다른 반 동명이인을 자동 연결하지 않는다. 정렬해도 원본 페이지 번호는 유지한다.
- 비활성 학생은 후보에서 제외한다(D4). 해당 행을 해결하려면 명렬에서 재활성화하거나 묶음에서 명시적으로 제외해야 한다.
- 여러 회차가 같은 학생에게 연결되는 것은 정상이다. 중복 기록 의심과 중복 학생 후보 오류를 구분한다.
- E5는 ‘보내기’의 차단 조건이다. 초안의 ‘매칭 전에는 다음 단계도 불가’는 추가 제한이다. 권고는 매칭을 먼저 마치는 흐름으로 하되, 원문 확인·저장·명렬 수정은 언제든 허용하는 것이다.
- ‘제외’로 일부만 보내는 정책은 **결정 필요**다. 허용한다면 제외 행은 전송 대상에서 명시적으로 빼고 별도 보관해야 하며, 미매칭 행을 몰래 건너뛰면 안 된다. 허용하지 않으면 전부 해결하거나 묶음을 분리하도록 안내한다.

### 2.8 AI 정제·보내기 검토 — [높음]

```text
+-----------------------------------------------------------------------+
| 3 AI 정제(선택)    대상: 2-3 / 진로·연간 / 30명 32건                  |
| 모델 [등록 모델 1 v]   학습 차단: 꺼짐   [설정]                       |
| [지침 설정 펼치기: 왼쪽 정제 지침 | 오른쪽 예시]                       |
|-----------------------------------------------------------------------|
| 기록 선택 목록  | 원문(로컬)        | 보낼 내용 / 정제 결과            |
| 20301 / 3/15    | 학번·이름 포함    | 식별정보 제거 표시               |
| 20301 / 4/02    | 원문 확인        | [수정] [이 내용을 사용]           |
|                 |                 | 후보 1 / 후보 2 / 후보 3          |
|-----------------------------------------------------------------------|
| [AI에 전송될 내용 확인] [선택 기록 정제] [AI 정제 건너뛰기]           |
| 다음 단계는 현재 사용할 내용이 정해진 기록으로 진행합니다.          |
+-----------------------------------------------------------------------+
| 4 보내기 검토                                                        |
| 항목 [진로·연간 v]  태그 [독서]  날짜 [3/15] 활동명 [진로 독서]       |
| 30명 / 32건 추가 · 기존 기록 덮어쓰기 없음                            |
| 김OO 2건 / 이OO 1건 ... [학생별 미리보기]                             |
| 미매칭 0 / 비활성 제외 1 / 마감된 대상 2명 ! [해결하기]               |
| [이전]                                 [30명에게 32건 보내기]       |
+-----------------------------------------------------------------------+
```

- 전송 내용 확인은 OCR 원문에만 적용하지 않는다. 붙여넣기·xlsx·직접 입력·지침·예시에도 학생 식별정보가 들어갈 수 있으므로 B3의 적용 범위와 제거 방식을 정해야 한다. 미리보기는 자동 제거 보장의 대체 수단이 아니다.
- ‘정제 건너뛰기’는 AI 호출만 생략한다. 이후 종합에 쓰일 내용의 식별정보 제거 원칙은 그대로 적용한다.
- 인박스 정제는 개별 기록을 정리하는 작업이다. 여러 회차를 하나로 합쳐 보내지 않는다(F1). 원본과 사용 내용을 구분하고 채택하지 않은 정제 결과를 임의로 보내지 않는다.
- 항목·명렬을 바꾸면 기존 매칭의 유효성과 적용 지침을 다시 확인한다. 서로 다른 명렬의 모든 학생을 무조건 보내지 않는다.
- ‘보내기 완료: 30명 32건 → 항목별 기록에서 보기’를 표시한다. 같은 묶음을 다시 보내 누가기록이 중복되지 않도록 재전송 정책이 필요하다.
- 마감 대상이 섞이면 자동으로 잠금을 풀지 않는다. 권고는 해당 대상 해결 전 보내기를 막고 이유를 표시하는 것이다. 일부 제외 허용 여부는 E5 및 마감 정책과 함께 결정한다.


- ‘이 기록만 정제’는 해당 카드에 두고, ‘선택 기록 종합’은 선택 건수 옆에 둔다. 아무 기록도 선택하지 않았을 때 버튼 옆에 이유를 표시한다.
- 비중은 일반 열람 중에 모든 카드에 붙이지 않고 ‘종합하기’ 설정에서 다룬다. 기록은 날짜·회차·출처·태그로 식별하고, 결과는 생성 시각과 작업 종류로 식별한다.
- 후보 열람·직접 편집·최종안 채택을 구분한다. 새 결과가 생겼다는 이유만으로 채택 최종안을 바꾸지 않는다. 채택본과 3개 후보 보관 관계는 §4에서 확정이 필요하다.
- ‘이미 쓴 생기부 넣기’는 **기존 완성문**임을 표시한다. 가져온 뒤 ‘최종안으로 채택’하거나 ‘다른 기록과 함께 종합’을 고른다. 여러 학생 xlsx는 대상 명렬 확인·매칭 미리보기를 제공하되 인박스로 강제 이동시키지 않는다(E8).
- 작은 창은 학생 목록을 접고 ‘누가기록 | 최종안’ 탭을 쓴다. 목록을 떠나도 필터·선택 학생·스크롤 위치를 유지하는 것을 권고한다.

### 2.10 문단 이동 — [높음]

```text
+-----------------------------------------------------------------------+
| 김OO / 진로 → 다른 항목으로 이동                                     |
| 원본 출처: 3/15 진로 독서 기록     이동할 문단 1개 선택됨              |
| [선택한 문단 미리보기 .............................................]  |
| 도착 항목 [자율 v] / 같은 학생 / 같은 학년도                          |
| 출발: 선택 문단 제거 → 도착: 별도 기록으로 추가                        |
| 도착 최종안 1490/1500B / 기록 추가 후 최종안 재검토 필요               |
| 대상이 마감 상태이면 먼저 마감을 해제해야 합니다.                    |
| [취소]                                              [문단 이동]      |
+-----------------------------------------------------------------------+
```

담임 항목 사이에는 ‘복사’ 선택지를 두지 않는다(F4). 문단 선택은 가능한 문단 경계를 눈으로 확인하게 하고, 이동 전후 항목과 학생을 함께 표시한다. ‘이동 취소’와 원자적 반영(출발만 삭제되는 상황 방지)은 추가 요구사항으로 권고한다.

누가기록 문단을 옮겼다고 채택 최종안의 문장이 저절로 이동되지는 않는다. 최종안 문단까지 이동 가능한지, 최종안 바이트를 어떻게 다시 계산할지는 명확히 정해야 한다. F4의 ‘이동 후 분량 초과’가 어떤 텍스트의 분량인지 §4에서 다룬다.

### 2.11 학생별 종합 설정·일괄 종합 — [높음]

학생별 종합은 학생 편집기의 ‘종합하기’에서 열고, 일괄 종합은 같은 처리 설정을 여러 학생에게 적용한다. 두 경로가 별도 결과를 만들지 않게 한다.

```text
+-----------------------------------------------------------------------+
| 종합 설정 / 공통수학1·1학기 / 김OO                                   |
| 선택 기록 | 비중 직접 지정 | 적용 예상 분량 (목표 1500B)              |
| 실험 관찰 | 60%           | 약 900B                                  |
| 발표 기록 | 비워 둠       | 남은 비율 자동 배분: 40%, 약 600B         |
| [ ] 비중 합계 100% 검사  합계·남은 비율·경고 표시                     |
| [ ] 성취기준 사용  성취기준 [등록본 v] 성취수준 [명렬값 B v]          |
| 모델 [등록 모델 1 v]  목표 [1500]B                                   |
| 지침 [................................] | 예시 [...................] |
| 예시가 있으면 함께 전송합니다. [AI에 전송될 내용 확인]                |
| [취소]                                       [종합 실행: 1명]       |
+-----------------------------------------------------------------------+
| 일괄 종합 / 항목 [공통수학1·1학기 v]                                 |
| 반 [전체] 상태 [입력 중] / 전체 활성 30명 / 선택 20명                  |
| 학생       | 기록 | 성취수준 | 처리 가능 여부                         |
| 김OO       | 4건  | B        | 가능                                   |
| 이OO       | 0건  | 미입력   | 성취기준만 생성 선택·수준 입력 필요     |
| 박OO       | 2건  | A        | 후보 3개 모두 보관 잠금                 |
| 최OO       | 3건  | C        | 마감 상태                              |
| 실행 17 / 확인 필요 3 [문제 학생 보기]                                |
| [학생별 기록·비중 확인] [공통 지침·예시] [실행 전 검토]                |
+-----------------------------------------------------------------------+
```

- 선택하지 않은 기록은 비중 자동 분배 대상에 섞지 않는다. 비중은 결과 분량의 **목표 비율**이며 실제 결과의 정확한 바이트 보장은 아니라는 짧은 설명을 둔다. 적용 예상치와 실제 결과 바이트를 구분한다.
- 기록 없는 세특 학생은 ‘기록 없음, 성취기준으로 생성’을 명시적으로 선택하고 수준을 묻는다(G4). 명렬값은 기본 입력만 해 주고 실제 선택값을 확인할 수 있게 한다. 다른 항목에 이 경로를 노출하지 않는다.
- 여러 학생의 기록 수가 다르므로 하나의 비중표를 전원에게 무조건 덮어쓰지 않는다. 권고는 기본 균등 배분, 필요한 학생만 개별 조정이다. 개별값·공통값 적용 우선순위를 결정해야 한다.
- 3개 모두 잠긴 학생은 실행 전에 알려 불필요한 호출을 막는다(G3). 마감·비활성·수준 누락 등 제외 사유와 실행 인원을 보여주고 선택 범위를 바꾸었음을 숨기지 않는다.
- **[중간] 진행 화면**: ‘완료 12 / 실패 1 / 대기 7’, 현재 단계, 경과 시간, ‘중지 요청’을 제공한다. 중지 시 이미 요청한 작업의 처리와 남은 작업 범위를 설명한다. 완료 후 실패 대상만 재시도하고 성공 결과를 다시 생성하지 않는 것을 권고한다.

### 2.12 최종안 검토·마감 — [높음]

```text
+-----------------------------------------------------------------------+
| 최종안 검토 / 김OO / 공통수학1·1학기                                 |
| 채택본: 11/7 14:10 종합 결과  [직접 수정]                             |
| 본문 ................................................................ |
| 1480 / 목표 1500B    근거 기록 4건 [기록 확인]                         |
| ! 채택 후 추가된 기록 1건 → [비교하고 재검토]                         |
| [ ] 내용을 검토했습니다.              [마감하여 편집 잠금]           |
|-----------------------------------------------------------------------|
| 마감 후: 상태 ‘마감’ / 편집 잠김 / 조회·복사·내보내기 가능            |
| 계속 수정하려면 [마감 해제] → 다시 편집·검토                          |
+-----------------------------------------------------------------------+
```

F5의 체크박스는 명시적인 마감 동작으로 유지하되, 상태·효과를 바로 옆에 설명한다. 최종안 채택은 자동 파랑, 교사의 마감은 초록으로 구별한다. 보관 잠금은 “새 결과 생성 시 이 후보를 자동 삭제하지 않음”이다.

권고는 최종안이 없으면 마감을 막는 것이다. 목표 바이트 초과·채택 후 기록 변경은 검토 경고로 표시하고, 초과 시 마감까지 차단할지는 결정해야 한다. ‘목표 분량’은 확정된 NEIS 상한 규칙이 아니므로 이 앱의 수치만으로 법정·시스템 입력 가능 여부를 보증하지 않는다.

3학년 동아리는 같은 화면 안에서도 학생마다 ‘1학기 말 마감 대상 / 연말 마감 대상’을 표시한다. 일반 학기 토글로 연간 항목을 반으로 나누지 않는다. 담임 3학년의 마감 범위와 실제 날짜는 구분한다(C5, C7).

### 2.13 항목별 조회·내보내기 — [높음]

```text
+-----------------------------------------------------------------------+
| 검토·내보내기  2026학년도                                            |
| 항목 [세특 v] 담당 [공통수학1·1학기 v]                               |
| 내보낼 상태 [마감만 v]  정렬 [학번순 v] [열·복사 범위 설정]           |
| 마감 24 / 미마감 5 / 최종안 없음 1 / 비활성 제외 2                    |
| [미마감 포함] 선택 시 포함할 최종안과 경고 표시                       |
|-----------------------------------------------------------------------|
| 선택 | 학번  | 이름 | 상태 | 채택 최종안       | 바이트               |
| [v]  | 20301 | 김OO | 마감 | ...               | 1480/1500            |
| [v]  | 20302 | 이OO | 마감 | ...               | 1320/1500            |
|-----------------------------------------------------------------------|
| 24명 / 한 행 한 학생 / 셀 병합 없음 / 화면 정렬과 같은 순서           |
| 복사 범위: [학번·이름·최종안 | 최종안 열만]  헤더 [포함/제외]         |
| [클립보드 복사: 24명]                         [xlsx 저장: 24명]       |
| 내보내기 성공 / 마감 상태는 그대로 / [미마감 검토로 돌아가기]         |
+-----------------------------------------------------------------------+
```

- ‘마감만’ 기본값은 안전한 권고이며 I2에 명시된 강제 조건은 아니다. 미마감 최종안을 내보낼 수 있는지 먼저 결정한다. 최종안 없는 학생을 빈칸으로 넣을지 제외할지도 명시해야 한다.
- xlsx와 복사는 같은 대상·순서·채택본을 쓴다. 학생 이름은 로컬 내보내기에 포함할 수 있으며 AI 전송 제외와 혼동하지 않게 한다.
- 본문 내부 줄바꿈은 한 학생 셀 안에서 유지하고, 클립보드에서 학생 행 경계와 섞이지 않게 해야 한다. NEIS 붙여넣기 적합성은 실제 대상 환경에서 확인할 검증 항목이다. 자동 NEIS 입력 기능은 요구사항에 없다.
- 복사 후 ‘24명 최종안 복사됨’, 저장 후 파일 위치와 결과를 표시한다. 내보내기 성공을 NEIS 반영 완료로 표시하거나 자동 마감하지 않는다.

### 2.14 보조 관리 화면 — [중간]

```text
+-----------------------------------------------------------------------+
| 설정 [연결·모델] [역할·학년도] [분량·일정] [프롬프트]                 |
| 모델 슬롯 1~4: ID / 사용 상태 / 작업 시 선택                           |
| OpenRouter 학습 차단 [꺼짐] / 무료 모델 제한 설명                      |
| [키 초기화] 키만 제거, 학생 기록 삭제와 구분                           |
|-----------------------------------------------------------------------|
| 프롬프트: 항목 [진로 v] 작업 [정제 / 다듬기 / 종합]                   |
| 지침 [...........................] | 예시 [...........................] |
| 로컬 저장 상태 / [기본값으로 되돌리기]                                |
|-----------------------------------------------------------------------|
| 성취기준: 과목 [공통수학1 v] [붙여넣기] [텍스트 PDF] [hwpx]           |
| 내용 미리보기·수정 / 성취수준 체계 [3단계 / 5단계]                    |

+-----------------------------------------------------------------------+
```

기본 프롬프트는 G7대로 임시임을 관리 화면에 표시한다. 생성 화면은 현재 적용한 항목·작업 종류를 요약하고, 모든 편집 가능한 지침에는 예시를 나란히 둔다. 태그는 등록 목록 선택만 허용한다(F3). 태그 이름 변경·삭제 시 기존 기록 처리도 결정해야 한다.

## 4. 요구사항 충돌·누락·결정이 필요한 부분

확정 요구사항 자체의 직접 충돌은 제한적이다. 대부분은 상호작용할 때의 규칙이 비어 있거나, 참고 앱·초안과 충돌하는 문제다. 아래에서는 이를 구분했다.

## 5. 구현 전에 확인할 대표 시나리오

아래는 구현 후 교사와 함께 점검할 수용 시나리오다. 실제 실행 검증을 완료했다는 의미는 아니다.

1. **[높음] 첫 사용·텍스트 입력**: OpenRouter만 설정한 비담임 교사가 과목을 만들고 명렬을 건너뛴다. 붙여넣기 후 명렬 등록으로 이동했다 돌아와 매칭·정제 생략·보내기까지 이어지며 입력 자료가 남아 있어야 한다.
2. **[높음] OCR 예외**: 학생당 2쪽인 61쪽 PDF에 동명이인·학번 누락·비활성 학생이 섞여 있다. 원본 페이지로 경계를 확인하고 매칭을 해결하기 전에는 보내지지 않아야 한다. AI에는 식별정보가 포함되지 않아야 한다.
3. **[높음] 최종안 보호**: 후보 3개 중 채택본을 보관 잠금한 뒤 다시 종합한다. 삭제되는 후보를 알 수 있고 채택본은 보존되어야 한다. 3개 모두 잠기면 호출 전에 중단되어야 한다.
4. **[높음] 마감 후 유입**: 마감한 학생이 포함된 묶음을 보내거나 일괄 종합한다. 잠금 해제 없이 기존 마감본과 기록이 바뀌지 않아야 하며, 해결할 학생과 이유가 보여야 한다.
5. **[높음] 혼합 학년 동아리**: 1·2·3학년 학생이 있는 연간 동아리에서 세특 학기 필터를 바꾼다. 동아리는 계속 표시되고 3학년에게만 1학기 말 마감 안내가 적용되어야 한다.
6. **[높음] 문단 이동**: 진로의 문단을 자율로 옮긴다. 출발·도착에 동시에 남지 않고 출처를 확인할 수 있어야 한다. 영향받은 최종안의 재검토 및 분량 경고를 확인한다.
7. **[높음] 내보내기**: 미마감·최종안 없음·비활성 학생을 섞고 화면 정렬을 바꾼다. xlsx와 복사가 미리보기와 같은 대상·순서·채택본이며 한 행 한 학생이고 비활성 학생은 제외되어야 한다.
8. **[중간] 기작성문과 기준만 생성**: 기존 완성문을 인박스 없이 넣어 다듬기/채택하고, 별도의 기록 없는 세특 학생은 성취기준·성취수준을 확인해 생성한다. 두 경로의 출처와 상태가 구별되어야 한다.
9. **[중간] 재개·작은 화면**: 일괄 실행 중 일부 실패·중지 후 재개하고, 좁은 창에서 기록과 최종안을 번갈아 검토한다. 성공 결과·선택 학생·입력 내용이 유지되고 버튼이 화면 밖으로 사라지지 않아야 한다.

먼저 확정할 것은 R03–R14의 전송·보존·잠금·마감·내보내기 규칙이다. 그 위에서 명렬 복귀 경로와 학생 편집기를 설계하고, 일괄 처리와 시각적 편의를 추가하는 순서를 권고한다.
