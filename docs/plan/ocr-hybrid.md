# OCR 하이브리드 (CLOVA + Qwen 비전) 계획

정한 날: 2026-11-22. 바탕 자료: 사용자가 준 'OCR 보조기능 Qwen 연동 개발계획'(일반 인쇄 문서용)을 착즙기(학생 학습지, 손글씨)에 맞게 줄임.

## 확정한 결정

1. **OCR 방식 세 가지**: CLOVA만(지금과 같음) / AI만(시험 기능, CLOVA 키 없이) / 하이브리드(키가 둘 다 있으면 추천).
2. **하이브리드 비교**: 같은 페이지를 CLOVA와 Qwen이 따로 읽는다(Qwen 요청에 CLOVA 결과를 넣지 않음). NFC·띄어쓰기 무시로 글자 단위 비교(`difflib`).
   - 같은 곳은 확정, 다른 곳은 "차이 n곳".
   - 차이마다 CLOVA 글자 위치(boundingPoly)로 원본 그 줄을 잘라 확대해 보여 준다. 고르기: [CLOVA] [AI] [직접 고치기].
   - 비슷한 정도가 낮은 페이지(표·두 단·그림 속 글자 많음)는 "크게 다름 — 페이지 통째로 비교".
3. **미검토 처리**: 검토하지 않은 차이는 CLOVA 쪽을 쓰고 "미검토 n곳" 표시만(다음 단계를 막지 않음). 페이지마다 [이 페이지 모두 AI 쪽] 버튼.
4. **API 호출은 묶음당 처음 한 번만**: CLOVA·Qwen 원 응답을 저장하고, 비교·확대 그림·다시 묶기는 저장 결과와 이 PC 안의 PDF만 쓴다. [OCR 다시 하기]는 과금 경고 확인 뒤에만. 한쪽만 읽은 묶음은 빠진 엔진만 한 번 더 부를 수 있다.
5. **글자 보정(그림 없이)**: 검토 창의 [AI 보정 제안 받기] 버튼(자동 아님). 설정의 **'OCR 보정 모델'** 칸(기본은 싸고 빠른 모델)을 쓴다.
   - 차이 구간 + 앞뒤 문맥 + 두 후보만 보내고, 보내기 전에 `strip_ids`로 학번·이름을 지운다.
   - AI는 CLOVA / Qwen / 합친 것 중 고르고 짧은 이유. 두 후보에 없는 낱말을 만들면 "⚠ 새로 만든 글자"(대원칙: 지어내지 않기).
   - 제안은 세 번째 후보로 미리 골라 두기만, 확정은 사람.
6. **그림 설명**: Qwen 호출(같은 한 번)에서 `figures: [{after_line, desc}]`도 받는다. 본문에 `[그림: …]` 표시로 넣고 글자 비교에서는 뺀다. 보이는 것만, 행위 추측 금지. 페이지마다 켜고 끄기(기본 켬).
7. **개인정보**:
   - 하이브리드는 Qwen에 보낼 그림의 머리글(기본 위 12%, 미리보기로 조절)을 흰색으로 가린다. 학번·이름은 CLOVA 결과로 찾는다.
   - AI 단독은 첫 사용 때 동의(이름이 담긴 그림이 OpenRouter로 감)를 받고 전체 전송, 또는 가리고 보내고 학생 짝짓기는 손으로(선택).
   - Qwen 그림 호출은 설정과 상관없이 **학습 차단(`provider.data_collection: deny`)을 항상** 켠다. 받는 제공업체가 없으면 보내지 않고 알린다.
   - 보안 / 개인정보 탭(`data-ntab-content="security"`) 문구를 고친다.

## 빼는 것 (원 계획서 대비)

좌표 정렬 동적 계획법, Qwen 좌표, 승인 이력·undo 스택, Windows 자격 증명 저장소(키는 지금 방식), 예산 예약, 정식 CER 평가 세트, 선택 영역 그림 재판독.

- 오류 유형: 받침·비슷한 글자(기포→기도, 열→엽/얼, 잎→일/입, 재야→해야), **세 모델 모두 '실험햇다'를 '실험했다'로 고쳐 씀**(교정 금지 지시를 어김, 단 합성 글씨에서 ㅆ/ㅅ 구분이 애매할 수 있음), 235B는 '골라' **빠뜨림**, 8B는 '물과' **끼워 넣음**.
- 그림 설명: 1쪽은 세 모델 모두 맞게 설명. **30B는 그림이 없는 2쪽에 '손으로 그린 식물 그림'을 지어냄.**
- 한계: 글꼴로 만든 깨끗한 합성 손글씨라 실제 학생 글씨보다 훨씬 쉽다. 실자료 효과는 미검증.
