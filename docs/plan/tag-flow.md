# 태그 중심 AI 변환 — 결정된 설계 (2026-11-13)

## 흐름
1. 같은 종류 자료를 인박스 등으로 넣으며 같은 태그를 붙인다(한 태그는 한 항목에만 쓰임).
2. 태그별 기록 › [이 태그 AI 변환]
   - 시험: 기록 1건(필요하면 몇 건 더)을 골라 프롬프트를 고쳐 가며 변환. 변환할 때마다 후보가 쌓임(3칸, 잠금, 후보마다 사용 프롬프트 표시).
     - 보낼 글: 처음 원문(기본) / 지금 기록 내용 / [이 후보를 더 고치기](짧은 요청 한 줄, 필요하면 전체 프롬프트 펼쳐 고치기).
   - 확정: 마음에 드는 후보 [확정] → 그 기록의 결과(기록 내용 교체·원문 보존) + 그 후보를 만든 단계(원문→1차→2차 프롬프트)가 태그의 확정 설정.
   - 나머지 변환: 지금 화면 조건(반·수업·항목·상태·검색) 기준 대상 목록, 체크로 제외 가능([모두 선택]·[선택 해제]·[변환 안 한 것만 선택]). 이미 반영한 기록은 체크 해제로 시작. 기존 완성문은 체크 해제로 따로 표시(넣을 수 있음). 확정한 단계를 그대로 재현. 확인 창에 건수·AI 호출 수·샘플 기준 예상 비용, 잔액 부족 경고. 실행 시작 때 대상 고정. 다른 항목 기록이 섞이면 알리고 항목별로 나눠 실행.
   - 검토·반영: 학생 | 원문 | 결과(편집) | 체크(처음 비어 있음, [모두 체크]) → [체크한 n건 기록에 반영]. 그사이 원문이 바뀌었거나 마감된 기록은 빼고 알림. [이번 반영 되돌리기](앱 재시작 후에도, 이후 직접 고치거나 마감한 기록은 제외하고 이유 표시).
3. 항목별 기록(학생별)에서 여러 태그 자료 확인·개별 추가·추가 AI → 종합 → 최종안 → 마감. 태그 반영은 최종안을 자동으로 바꾸지 않음(확인 필요 표시).

## 저장
- 태그 변환 후보는 일반 정제 후보(results 3칸)와 따로 3칸.
- 작업·시험 후보·확정 단계·일괄 결과·반영 이력을 학년도 DB에 저장(재시작 후 이어 하기·되돌리기).
- 프롬프트는 태그 작업 안에 저장, 확정 때 체크하면 💬 프롬프트 목록에도 저장. 목록을 나중에 고쳐도 확정한 작업에는 영향 없음.

## 메뉴·안내
- 메뉴 순서를 흐름대로: 현황판 → 자료 인박스 → 태그별 기록 → 항목별 기록 → 검토·내보내기.
- 인박스 보내기 끝 → [이 태그로 AI 변환하기], 태그 반영 끝 → [바뀐 학생들 항목별 기록에서 보기], 현황판 다음 할 일에 진행 중 태그 작업.

## 단계별 릴리스
1. 저장 기반(형식 v12·마이그레이션·백업 시험), 메뉴 순서 변경
2. 시험 후보·이어 고치기·확정·한 건 반영·되돌리기
3. 확정 단계로 나머지 일괄 변환(대상 목록·비용 확인·중지·실패만 다시)
4. 검토 표·일괄 반영·작업 단위 되돌리기, 화면 연결·현황판 안내

검토 근거: Codex 검토(위험 R01~R15 — 후보 슬롯 충돌, 입력 고정, 충돌 검사, 반영 이력, 대상 고정 등).
