## 판단과 우선순위

AI 실행 전 대상과 모델을 확인하고, 실행 중 경과 시간과 결과를 보여주는 흐름은 이전보다 예측하기 쉽다. 학생 묶음과 마감 통계도 담당 전체의 작업량을 파악하는 데 도움이 된다. 학생별 2학기 목표가 AI 호출까지 반영되는 기본 경로와 일괄 작업의 현재 건 완료 후 중지 동작은 확인했다.

출시 전에 우선 해결할 문제는 **성취기준 내용이 빠져도 보존 검사가 통과하는 경우(V01)**와 **학생 묶음을 접으면 펼침 버튼도 사라지는 CSS 충돌(V02)**다. 나머지는 중간 16건·낮음 1건으로, 총 19건이다. 특히 상태 색은 토큰 자체는 맞지만 선택·묶음·단계 표시가 같은 색을 다른 의미로 사용하므로, 현재 화면 전체를 색만으로 판독할 수 있다고 보기는 어렵다.

심각도는 높음=자료 손실 또는 핵심 작업 접근 차단, 중간=잘못된 판단·재실행·설정 실수 가능성, 낮음=보조 조작·안내 개선으로 정했다. 아래에는 확인된 동작과 사용성 위험을 구분했으며, 단순 개선 제안을 요구사항 위반으로 취급하지 않았다.

## 상세 검토

### V01. AI가 내용 줄을 머리글로 판단하면 삭제돼도 보존 검사 통과

- **심각도:** 높음
- **위치:** `app/stdformat.py:75–88`, `122–124`, `160–175`; `app/api.py:919–926`; `app/web/app.js:3245–3256`
- **문제:** AI가 미분류 줄을 `header`로 정하면 정리본에서 빼고, 같은 역할 목록을 사용한 검증에서도 제외한다. 삭제 판단과 보존 검사가 독립되어 있지 않다. 내용이 빠져도 ‘한 글자도 바뀌지 않고 모두 들어 있습니다’라는 초록 성공 안내와 적용 버튼이 나온다.
- **사용자가 겪는 상황:** 코드 없이 적힌 성취기준 설명·유의사항을 AI가 머리글로 오판한다. 교사는 보존 검사를 믿고 정리본을 적용해 원문 내용을 잃는다. 삭제 줄이 보조색 안내에 나열되더라도 강한 성공 문구와 모순된다.
- **확인:** `수학적 모델링의 의미를 이해한다.`를 미분류 줄로 두고 AI 응답을 `{"0":"header"}`로 대체했다. 해당 문장이 정리본에서 사라졌는데 `missing=[]`로 통과했다. 실제 AI가 항상 오판한다는 주장이 아니라, 오판 때 보호 장치가 작동하지 않는다는 재현이다.
- **제안:** 확실한 표 머리글만 규칙으로 제외하고, AI가 제안한 삭제는 별도 목록에서 교사가 확인하게 한다. 보존 검사는 원래 줄을 기준으로 수행하고, 사용자가 승인한 삭제만 예외로 둔다. 적용 전 원문을 보관하고 되돌리기를 제공한다. 성공 문구도 공백·수준 기호·승인된 머리글 제외 등 실제 검사 범위를 설명해야 한다.

### V02. 학생 묶음을 접으면 다시 펼칠 제목 버튼까지 숨음

- **심각도:** 높음
- **위치:** `app/web/app.js:1645–1654`; `app/web/style.css:514`, `575–578` — 학생 목록 묶음
- **문제:** 접힌 묶음은 `stu-group folded`가 되고 제목은 `.stu-group-head` 버튼이다. 전역 규칙 `.folded > :not(.sec-title:first-child) { display:none !important; }`가 이 버튼에도 적용된다. 제목이 `.sec-title`이 아니므로 펼침 버튼도 숨는다. 접기 상태까지 저장되어 재진입해도 이어질 수 있다. DOM 생성과 CSS 선택자 대조로 확인한 충돌이며 실제 창 클릭은 하지 않았다.
- **사용자가 겪는 상황:** 한 반을 접었더니 반 이름과 펼침 버튼이 사라진다. 학생이 삭제됐다고 오해하거나 목록을 원상 복구할 방법을 찾지 못한다. 검색·필터를 쓰면 강제로 펼쳐지지만, 해제하면 저장된 접힘 상태로 돌아간다.
- **제안:** 기존 기록 칸 접기 CSS의 적용 대상을 한정하고 학생 묶음은 전용 접기 규칙을 사용한다. 접혀도 이름·인원·마감 수·펼침 버튼을 항상 남긴다. 저장된 접기 상태를 가진 경우까지 확인해야 한다.

### V03. B·D 기호 자체가 없는 A·C·E 자료는 3단계로 인식하지 못함

- **심각도:** 중간
- **위치:** `app/stdformat.py:101–114`; `app/standards.py:130–131`
- **문제:** 3단계 표시는 B·D 기호가 존재하면서 설명이 비어 있을 때만 붙는다. 원문에 `A: 설명 / C: 설명 / E: 설명`만 있으면 `three_level=[]`다. 그 결과 학생 B는 A 설명, D는 C 설명을 참조하라는 추가 AI 지침도 들어가지 않는다. 그 밖의 누락 수준 역시 아예 기호가 없으면 ‘원문에 내용 없음’ 표시가 생기지 않는다.
- **사용자가 겪는 상황:** 불필요한 빈 B·D 행을 이미 지운 교육과정 자료를 붙여넣는다. 같은 3단계 내용인데 정리 결과와 AI 반영이 달라진다.
- **확인:** `[10수학-01] …` 뒤 A·C·E 세 설명만 넣어 빌드했을 때 보존 검사는 통과하지만 3단계 표시는 없었다.
- **제안:** 성취기준별 A~E 전체를 기준으로 기호가 없거나 설명이 빈 수준을 함께 판단한다. A·C·E만 내용이 있으면 동일한 3단계 처리로 통일한다. 자료의 A·C·E 설명 체계와 명렬의 3단계 A·B·C 선택은 서로 다른 개념임도 안내한다.

### V04. 잘못된 AI 역할 응답에서 이해하기 어려운 오류 또는 조용한 대체 처리

- **심각도:** 중간
- **위치:** `app/stdformat.py:75–88`, `134–136`; `app/web/app.js:3233–3251`
- **문제:** A~E 기호가 아닌 문장을 AI가 `label`로 답하면 `m.group(1)`에서 오류가 난다. JSON이 틀리거나 역할이 빠지면 모두 `text`로 대체하는데, UI는 ‘AI로 역할을 정한 줄 N줄’로만 표시해 대체 여부를 알 수 없다. 정리용 모델 선택 요소도 생성만 하고 화면에는 붙이지 않아 이 경로에서 모델을 직접 고를 수 없다.

### V05. 정리본 적용 실패 때 편집 내용과 저장 상태가 어긋날 수 있음

### V12. 합산 연결 뒤 목표의 우선순위와 0B 처리 안내가 일관되지 않음

- **심각도:** 중간
- **위치:** `app/db.py:338–361`; `app/records.py:54–69`; `app/web/app.js:511–517`
- **문제:** 연결할 때는 2학기→1학기 여부를 검사하지만, 나중에 일반 설정에서 학기를 바꿀 때 기존 연결의 유효성을 다시 확인하지 않는다. 계산은 `pair_id`를 따라 계속된다.
- **사용자가 겪는 상황:** 학기 설정 실수를 고친 뒤 화면에는 2학기 과목 두 개가 있는데, 한 과목이 다른 과목을 여전히 ‘1학기’로 차감한다.
- **확인:** 정상 연결 후 1학기 과목의 `semester`를 2로 바꾸는 요청이 성공했다. 2학기 학생 화면 데이터의 연결 상대는 `공통수학1·2학기`이고 차감 목표도 계속 적용됐다.
- **제안:** 학기 변경 전에 연결된 과목을 안내하고 연결 해제/재설정 후 저장하게 한다. DB와 조회 경로에서도 연결 역할을 재검증한다. 같은 1학기에 여러 2학기를 연결할 수 있는지 역시 명시해야 한다. 현재 1학기 안내는 첫 연결 하나만 보여주므로 다중 연결을 허용한다면 전체 상대를 보여줘야 한다.

### V15. 선택·묶음·현재 단계의 색이 완료·마감 상태와 겹침

- **심각도:** 중간
- **위치:** `app/web/style.css:241`, `256`, `403`, `410`, `575–580`, `597–606`; `app/web/app.js:1667`, `2721`, `2548–2549`
- **문제:** 파랑은 마감·현재 선택·현재 단계에 사용되고, 초록은 완료·선택한 명렬 탭·일부 묶음색·체크 선택 행에 사용된다. 학생 목록의 선택 강조는 6색 묶음마다 달라 다른 화면의 선택 규칙과도 다르다. 내보내기는 미마감에 경고 배경을 사용하고 마감에 공통 파랑 배지를 쓰지 않는다. 상태 토큰 변경만으로 화면 전체의 의미가 통일되지는 않았다.
- **사용자가 겪는 상황:** 파란 담당 카드를 보고 모두 마감했다고 생각하지만 단지 선택된 카드다. 초록 수업 띠를 보고 완료한 수업이라고 생각한다. 인박스의 생략한 AI 정제 단계에도 초록 ✔가 붙어 AI를 실행한 것으로 오해할 수 있다.
- **제안:** 앞의 화면별 점검표처럼 상태·선택·그룹 식별을 분리한다. 생기부 상태 배지를 학생 목록·현황판·내보내기에 공통 적용하고 항상 글자/기호를 함께 제공한다. 선택은 ‘선택됨’과 고정된 비색상 표시로 통일한다. 선택적 단계를 건너뛰었으면 `건너뜀`으로 표시해 ‘완료’와 구별한다. 색만으로 모든 정보를 읽도록 요구하기보다 색이 다른 의미를 주장하지 않게 해야 한다.

### V16. 통계 상자의 상태 칩은 모두 기본색으로 표시됨

- **심각도:** 중간
- **위치:** `app/web/app.js:1675–1680`; `app/web/style.css:215–218`, `587–589`; 제공 `v15_color_records.png`
- **문제:** 칩에는 `st-final`·`st-progress`·`st-none`이 붙지만 뒤의 `.stat-chip`이 같은 우선순위로 글자색을 덮는다. 숫자도 `.stat-chip b`의 기본색이다. 그래서 최종안·입력 중·기록 없음 칩에서 기대한 초록·노랑·회색을 볼 수 없다. 선택된 칩은 상태와 무관한 파랑이 된다.
- **사용자가 겪는 상황:** 위 통계와 아래 학생 아이콘이 같은 상태를 다른 색으로 보여줘 범례를 익히기 어렵다. 통계 4명을 눌러도 검색어가 남아 있으면 일부만 보여 숫자가 틀렸다고 생각할 수 있다.
- **제안:** 칩의 상태 아이콘/배지는 상태 색을 유지하고 선택 테두리는 별도 처리한다. `담당 전체 통계·검색 결과 N명`을 구분해 표시하고 클릭 시 검색 유지 여부를 알린다. 현재 마감 숫자는 버튼이 아니므로 마감 학생 바로 보기 동작을 제공하면 다른 칩과 조작도 맞아진다.

### V17. 성취기준을 직접 입력·삭제하면 목록 완료색이 즉시 따라오지 않음

- **심각도:** 중간
- **위치:** `app/web/app.js:3190–3191`, `3203–3206`; `app/standards.py:105–110`
- **문제:** 직접 편집 자동 저장은 ‘저장됨’만 갱신하고 왼쪽 과목 목록의 `has`·완료 클래스를 갱신하지 않는다. 빈 과목에 직접 붙여넣거나 입력된 과목을 모두 지운 뒤에도 목록은 화면 재조회 전까지 예전 색이다. overview는 공백만 있는 텍스트도 길이가 있으면 입력됨으로 센다.
- **사용자가 겪는 상황:** 저장됐는데 과목은 계속 ‘아직 없음’이라 다시 붙여넣는다. 반대로 내용을 모두 지웠는데 초록 완료라 성취기준이 남아 있다고 생각한다.
- **제안:** 저장 성공 결과로 목록의 입력 여부·시간·색을 함께 갱신한다. 실제 내용은 `trim()` 기준으로 판단한다. ‘저장 성공’ 초록과 ‘자료 있음’ 초록은 각각 해당 위치의 사실을 나타내야 한다.

### V18. 수업 이름을 비웠을 때의 동작이 입력 경로마다 다름

- **심각도:** 중간
- **위치:** `app/web/app.js:610–626`, `724–730`, `923`; `app/db.py:440–445`; `app/web/app.js:1613–1617`
- **문제:** 명렬 추가 창은 수업 이름을 비우면 학년-반으로 묶는다고 설명하지만, 기존 학생을 추가 입력할 때 빈 수업 값은 기존 수업을 유지한다. 실제 해제는 별도 ‘수업 지정’에서 빈 값으로 저장해야 한다. 또 과목에 수업 지정 학생이 한 명이라도 있으면 미지정 학생은 학년-반 대신 ‘수업 미지정’ 한 묶음이 된다.
- **사용자가 겪는 상황:** 잘못 지정된 수업을 없애려고 추가 입력 창에서 이름을 비우지만 기존 수업이 그대로 남는다. 일부만 수업을 정한 뒤 나머지가 여러 반에서 한 묶음으로 합쳐져 당황한다. 파일 이름 기본값이 ‘명렬최종’ 같은 업무용 이름일 수도 있다.
- **제안:** 추가 입력에서 `빈 값=기존 수업 유지(새 학생은 미지정)`라고 표시한다. 기존 값 해제는 명시적 `수업 지정 해제` 버튼으로 분리하고 이름·대상 인원을 확인하게 한다. 수업 방식으로 전환되면 `미지정 학생은 ‘수업 미지정’으로 모음`을 안내한다. 파일에서 읽은 수업명은 입력 확정 전 검토 대상으로 강조한다.

### V19. 검색·필터 중 접기 버튼은 표시되지만 눌러도 접히지 않음

- **심각도:** 낮음
- **위치:** `app/web/app.js:1627`, `1636`, `1645–1651`
- **문제:** 검색·필터 중에는 항상 `folded=false`로 계산한다. 제목 버튼을 눌러도 다시 펼쳐진 채이고 저장된 접기 값만 바꾼다. 요구사항의 검색 결과 자동 펼침은 충족하지만 버튼은 접을 수 있는 것처럼 남는다. 검색 대상도 이름·학번만이어서 수업 이름으로 찾을 수 없다.
- **사용자가 겪는 상황:** ‘입력 중’ 필터에서 한 수업만 접으려는데 버튼이 반응하지 않는다고 느낀다. 필터를 지운 뒤 예상하지 못한 묶음이 접혀 있다. 수업이 많을 때 ‘물리학 A반’을 입력해도 학생이 나오지 않는다.
- **제안:** 자동 펼침 중에는 접기 버튼을 비활성화하고 이유를 표시하거나, 검색 중 임시 접기를 별도 지원한다. 필터 중 클릭이 평상시 접기 설정을 바꾸지 않게 한다. 수업·학년-반 검색 또는 묶음 선택 필터를 제공하면 큰 명렬 탐색이 쉬워진다.

## 검증 결과와 출시 전 확인

로컬 기본 테스트는 다음 세 개 모두 통과했다. 테스트는 임시 자료 폴더를 쓰고 AI·잔액 응답은 로컬 대체 함수로 처리한다. 사용자 실제 자료나 외부 AI 서비스를 사용하지 않았다.

| 실행 | 결과 |
|---|---|
| `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B tests/test_stdformat.py` | `STDFORMAT OK` |
| `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B tests/test_pair_subject.py` | `PAIR SUBJECT OK` |
| `PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B tests/test_roster_input.py` | `ROSTER INPUT OK` |

추가 재현에서는 AI 머리글 오판의 검사 우회, A·C·E만 있는 입력의 미인식, 잘못된 `label` 역할의 예외, 1학기 수정 뒤 2학기 마감·재검토 표시 유지, 연결 과목 학기 변경 후 잘못된 관계 유지, 본문 속 이름·학번의 대체 AI 함수 전달을 확인했다. 추출한 `aiRun` 모의 실행은 현재 건 완료 후 중지·남은 건 미실행, 개별 실패 후 다음 건 계속 처리되는 것을 확인했다. 브라우저 DOM·CSS 실측을 대체한 것은 아니다.

원문 검사에 관해서는 A·B·A처럼 반복 수준이 있는 입력이 재배치되면 순서 검사에서 누락으로 잡혀 적용을 막는 것도 확인했다. 따라서 보존 검사가 항상 무효한 것은 아니다. 문제는 V01처럼 AI의 삭제 판단 자체가 검사 제외 근거가 된다는 점이다. 또한 이 검사는 붙여넣은 텍스트와 정리본의 비교이므로 PDF/HWPX 복사 이전에 빠진 수식까지 보장하지 않는다. 수식 의심 안내를 접힌 보조 설명에만 두기보다 의심 줄로 바로 이동할 수 있게 하면 좋다.

Windows 출시 전에는 1366×768의 125%·150% 배율에서 긴 오류 메시지 5건, 긴 수업명, 학생 묶음 접기·재실행, 단건/여러 건 진행 창, 중지 직후 대기·재개를 실제 조작으로 확인해야 한다. 특히 `.ai-prog-card`는 높이 제한·내부 스크롤이 없어 긴 오류가 작은 화면에서 확인 버튼을 밀어낼 수 있다(`style.css:559`). 이 부분은 실측 전 위험으로 남긴다. 상태 구분은 흑백에서도 기호·글자로 확인 가능해야 하고, 작은 회색·노랑 상태 아이콘의 가독성도 실제 교실 모니터에서 확인하는 편이 좋다.

코드·설정·assets·다른 문서는 수정하지 않았다. Chrome 실행·외부 전송·git commit/push도 하지 않았다.
