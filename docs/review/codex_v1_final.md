# v1.0 최종 확인 (v0.35.3)

## 결론

- **아래를 고친 뒤 가능.**
- Windows의 기록 작성·가짜 AI 변환·마감·내보내기와 v0.35.0 → v0.35.1 배포본 업데이트·복원은 이전 시험에서 통과했다. 꾸러미 실패 복구도 이번 로컬 시험에서 통과했다.

- 현재 배포 코드의 Windows·Mac 최종 조작 확인, 백엔드 시험의 외부 의존 제거, 설명과 정식 버전 표시 정리가 남았다.

## 2. 바뀐 코드 점검

### F1. 스캔의 신원 정보가 남거나 정상 본문이 사라짐 (높음)

- 위치는 app/scan.py:11~21, 87~160, 184~193 및 app/inbox.py:817~828이다. 페이지마다 첫 쪽에서 찾은 값과 각 쪽에서 찾은 값을 차례로 지우며, 삭제 범위는 비어 있지 않은 첫 8줄이다.
- 오프라인 더미 시험에서 명렬이 비어 있을 때 `학번: 10399 / 이름: / 가나다 / 본문입니다.`는 본문만 남았다. 이름을 `반유진`으로 바꾸면 접두사 `반`이 라벨로 취급되어 이름이 남았다. `이름.` 뒤 단독 이름도 남았고, 여덟 번째 줄의 `이름:` 뒤 아홉 번째 줄 이름도 남았다. 슬래시는 줄 경계를 뜻한다.
- 반대로 `10399 / 탐구를 진행하였다.`는 `탐구를`을 이름으로 읽어 `진행하였다.`만 남겼다. `이름: / 탐구활동 / 실험을 진행하였다.`는 빈 이름 칸 뒤의 제목을 지웠다. 쌍점 조건은 다음 줄 전용 규칙에만 있고 같은 줄 규칙은 여전히 구분 기호가 선택이다. 첫 후보를 거절하면 다음 라벨 후보도 다시 탐색하지 않는다.
- 행 정제는 Inbox 내용 텍스트를 쓰므로 남은 이름이 이후 AI 입력에 포함될 수 있다(app/api.py:3235 이후). 이번 확인은 더미 문자열 변환까지다.
- 라벨 비교는 완전한 토큰과 구분 기호를 기준으로 하고, 삭제 범위는 이름 전체의 전역 치환 대신 신뢰할 수 있게 식별한 위치로 제한한다. 학생 후보 매칭과 전송용 지우기를 구별해 낮은 신뢰도에서는 본문을 자동으로 자르지 않고 전송 전 확인을 요구한다. 라벨 접두사 성씨, 구분자·줄 경계, 반복 라벨, 복수 쪽, 빈 명렬·빈 이름 칸을 회귀 시험에 추가한다.

### F2. OCR 화면이 이전 선택이나 다른 가림 비율을 보여 줌 (높음)

- app/web/app.js:7762~7776, 7845~7848은 SC.mode와 SC.mask를 새 PDF에서 초기화하지 않는다. 첫 선택은 CLOVA만이지만 양쪽 키로 Qwen·하이브리드를 선택한 뒤 다른 PDF를 고르면 이전 방식이 남는다. 같은 묶음의 재시도 선택은 보존하되 새 PDF에서는 초기화해야 한다.
- app/web/app.js:7890~7929는 화면에서 고른 SC.mask로 미리보기를 만든다. 기존 Qwen 결과가 있는 묶음은 app/api.py:2984~2997 및 app/inbox.py:657~675에서 저장된 비율을 재사용한다. 예를 들어 가림 0%에 이미 동의한 묶음을 일부 읽은 뒤 다시 열어 슬라이더를 12%로 높이면 미리보기는 가려지지만 남은 쪽은 저장된 0%로 처리될 수 있다. 코드 경로로 확인했으며 OCR 요청은 실행하지 않았다.
- 일반 시작 화면에서 슬라이더 0%도 '머리글을 가린' 것으로 안내하고, CLOVA 결과의 [Qwen으로도 읽어 비교하기]는 0%일 때도 '위 0%를 흰색으로 가린'으로 안내한다(app/web/app.js:7960~7967). 서버의 미동의 차단은 작동하도록 구현돼 있으나 이미 저장한 동의가 있으면 이 문구가 유일한 전송 설명이다.
- 모든 시작·재개·비교 경로에서 서버가 사용할 유효 비율을 UI에 노출한다. 재개 시 비율 고정과 이유를 알리고, 0%의 전송 설명·동의와 버튼 상태를 공통화한다. CLOVA 키만 있으면 CLOVA, OpenRouter 키만 있으면 Qwen, 둘 다 있으면 세 방식이 가능하다. 키가 모두 없으면 새 PDF 선택은 막지만 이미 고른 PDF는 비활성 하이브리드 라디오와 활성 시작 버튼이 함께 나타날 수 있으므로 renderScanStart에서도 시작을 막고 설정으로 안내한다.

### F3. 작은 미리보기와 가로 폭이 전송 전 판단을 어렵게 함 (중간)

- app/web/style.css:2203~2213의 88px 고정 높이 미리보기는 가림 경계나 머리글 전체를 숨긴다. 세로 A4를 폭 300px로 표시하면 전체 높이가 약 424px이고 25% 경계가 약 106px이므로 실제 가림 경계를 볼 수 없다. 첫 쪽 예시와 다른 쪽의 배치도 다를 수 있다.
- 같은 블록은 창 폭 1200px 이상에서 긴 경고를 nowrap으로 고정한다. 내부 패널 폭과 150% 본문 설정을 기준으로 확인하고, 줄바꿈을 허용한다. 마법사 Chat의 981px 이상 overflow:hidden과 채팅 최소 높이 120px(app/web/style.css:1068~1074)도 짧은 창에서 입력 줄이 잘리지 않는지 확인한다. 가림 경계를 볼 수 있는 전체 페이지 또는 확대 보기를 제공한다. 치수와 CSS에 근거한 판단이며 실제 화면은 확인하지 않았다.

### F4. 태그별 원문 동기화가 문자열 일치로 원문을 추정함 (중간)

- app/web/app.js:4895~4903, 4937, 4952의 저장·되돌리기·다시 불러오기는 단순 기록에서 W3를 해결한다. AI 확인과 마법사는 갱신된 r.orig를 읽는다(5370~5390).
- 별도 original이 있으면서 content와 우연히 같은 상태에서는 일반 content 저장으로 DB original이 바뀌지 않아도 UI가 r.orig를 바꾼다. 반대로 다른 곳에서 별도 original만 바뀐 뒤 현재 값 다시 불러오기는 원문을 갱신할 수 없다. app/records.py:359~366의 응답에는 원문과 확정 상태가 없고 :561~564와 :753~768에서 원문과 본문을 구별한다.
- 서버가 계산한 orig와 confirmed를 저장·되돌리기·다시 불러오기에서 반환해 화면에 반영한다. 별도 원문을 둔 기록, 같은 문자열, 충돌 후 다시 불러오기를 확인한다.

### F5. 안내 HTML과 결과 요약 (낮음)

- stepsHtml 사용 호출은 9곳이며 검색 결과 10줄 중 첫 줄인 app/web/app.js:471은 정의다. 학번·이름 목록(:1172), 백업 표시명(:1958), 누락 키 이름(:7767), 모델 표시명(:7965)은 escHtml 적용을 확인했다. 가림 퍼센트와 건수는 숫자다. 반영(:6344), 무가림 확인 두 곳(:7905, :7924), CLOVA 추가(:7973), 다시 읽기(:7978)의 나머지 내용은 내부 상수다. 별도 결과 삭제 안내도 이름을 escHtml 처리한다. OCR 노란 경고의 모델명 속성(:7890)도 이스케이프된다.
- typedConfirm({ html })의 현재 호출은 백업 복원 한 곳이다. 그 외 문자열은 :483~486에서 이스케이프하고 줄바꿈을 처리한다. 확인한 경로에서 외부 값의 미처리 HTML 삽입은 발견하지 않았다. stepsHtml은 호출부 이스케이프에 의존하므로 새 호출에서도 같은 규칙을 지킨다.
- 결과 요약은 항목별·태그별 모두 op가 orig인 항목을 제외하고, 원문뿐이면 최신 표기를 생략한다(:3004~3014, :5423~5429). eulReul(:479~481)은 받침 있는 '확인'에 '을'을 붙이며 정해진 확인 어휘에 맞는다. 비한글 어휘에는 '를'을 기본으로 쓴다.

### F6. 세모 감시와 스타일 적용 범위 (낮음)

- app/web/app.js:223~245에서 .tri 내부를 건너뛰므로 자체 DOM 교체로 후속 콜백을 한 번 더 만들 수는 있어도 같은 글자를 계속 다시 감싸는 루프는 보이지 않는다. textarea·select·option을 제외하고 button·summary 자손만 바꾸며, 현재 코드에서 contenteditable 사용은 찾지 못했다. 일반 입력값·본문 저장에는 영향이 보이지 않는다. 이름 등 사용자 표시 문자열의 세모도 감싸지만 textContent는 유지된다.
- document.body 전체 childList·characterData 감시는 큰 표를 다시 그릴 때마다 비대상 텍스트도 순회한다. 비용 실측은 없다. 대상 버튼을 만들 때 꾸미거나 감시 범위를 제한하고, 향후 contenteditable을 쓰면 그 하위도 제외한다.
- app/web/style.css:2250~2277의 details 선택자는 메뉴 두 종류만 제외한다. 사용자 정의 summary 표지와 중복 여부를 확인한다. span.tag는 기본 모서리만 바꾸고 눌리는 칩의 예외가 있으나 기존 비표준 클릭 칩의 크기는 화면에서 확인할 필요가 있다. button.link는 전역에 가까워 기존 인라인 버튼의 패딩·테두리·폭을 바꾼다. 단계 span의 !important는 현재 반지름에만 영향이 있고 단계 배지 안의 원형 숫자를 직접 덮지 않는다. 기존 컴포넌트에서 범위를 좁히고 좁은 창의 핵심 버튼 접근을 확인한다.

### F7. W10의 나머지 append와 PDFium (낮음)

- app/web/app.js:7874~7879, :8040 전후의 차이 검토 머리, :8168~8171의 OCR 진행에서 해당 조건부 자식은 빈 문자열 또는 필터를 거친다. `el(..., [...])`의 null과 native append 인수의 null은 구별했다. 직접 append·조건부 인수의 정적 검토에서 추가로 확정할 W10 재현은 찾지 못했다. 전체 화면 검증은 이전 버전 Windows 결과의 범위다.
- requirements.txt:5는 pypdfium2 5.15.2이고 로컬 설치도 같다. 스캔 페이지 렌더·가림 PNG와 병렬 렌더 시험이 통과했다. 새 exe에서 DLL 번들·프로세스 종료와 Mac 설치는 별도 확인 대상이다.

### F8. 백엔드 시험이 잔액 API까지 호출함 (중간)

- tests/test_fill_tidy.py:8~10은 chat만 대역으로 바꾼다. 첫 성취기준 채우기에서 app/api.py:1966~1968의 잔액 확인은 그대로 남는다. 외부 DNS를 차단한 시험에서 실패했고, 잔액만 메모리 대역으로 바꾼 개별 시험에서는 세 절 모두 통과했다. 앱의 성취기준 처리 실패가 아니라 시험의 외부 요청 경로다.
- 해당 시험에서 잔액 조회를 대체한다. CI에서 로컬 시험이 네트워크나 가짜 키 요청에 의존하지 않도록 전체 50개를 다시 돌린다.

## 3. 보안·개인정보 문구

- 사용 안내 3-1(app/web/index.html:626~638)의 기본 CLOVA, Qwen만 시험 기능, 하이브리드 설명은 초기 UI와 대체로 일치한다. CLOVA에는 가리지 않은 스캔 이미지가 간다(app/api.py:3020 전후). 보안 탭 :861의 '스캔 PDF는 … CLOVA OCR로 갑니다'는 'CLOVA만·하이브리드를 고르면'으로 한정해야 한다. Qwen만은 CLOVA를 호출하지 않는다.
- Qwen 선택 설명에서 경유지가 빠져 있어도 전송 경고, 설정(app/web/index.html:333~346), 보안 탭(:862)에 OpenRouter가 명시된다. app/ocr_vision.py:21, :59~94의 이미지 가림과 deny·ZDR 요청도 일치한다. 설정은 양쪽 방식의 0% 동의를 안내하지만 F2 때문에 실제 시작·재개 안내를 맞춰야 한다. 학습 차단과 보존 안 함은 라우팅 조건이므로 제공업체의 실제 운용을 이 시험으로 확인한 것은 아니다.
- 일반 글 AI에는 별도 명렬 필드를 넣지 않아도 본문에 들어간 식별 정보는 남을 수 있다. OCR 화면 app/web/app.js:7917과 사용 안내 :638의 이름 줄 제거는 F1에 비춰 보장으로 쓰면 안 된다. OCR 차이의 AI 제안은 별도 경로에서 가린 텍스트와 문맥을 전송한다(app/api.py:3113~3136, app/inbox.py:781~794). 보안 탭의 경고와 초록 칸(:860, :883~885)을 함께 읽어도 자동 제거 범위가 모호하므로 구조화된 명렬 필드와 본문을 명확히 구분한다.
- Google Forms는 app/web/app.js:386, :9422~9428 및 app/api.py:308~311에서 고정 응답자 URL을 브라우저로 연다. 현재 주소에는 버전·OS 자리표시자가 없고 진단 정보 복사는 별도 클릭이다. 보안 탭(:875, :885)과 설정(:512~519)의 설명은 앱 동작과 맞는다. 제출 전에 이름·학번·학교·기록·오류 메시지 및 첨부 캡처에서 개인정보를 제거하라는 안내를 버튼 가까이 둔다. 캡처·이메일 문항, Google 로그인 및 Drive·응답 시트 저장은 설문 소유자의 설정에 달려 있으며 외부 폼을 열지 않아 확인하지 않았다.
- OpenRouter 잔액 조회는 앱을 켤 때뿐 아니라 AI 결과 반환 과정에서도 일어난다(app/api.py:1966~1968). 내용과 키의 전송을 구분해 기술한다. GitHub 업데이트 조회, 브라우저에서의 맞춤법 검사와 진단 수동 복사 경로에는 기존 주의 문구가 있다.
