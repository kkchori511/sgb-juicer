## 문제 (심각한 순)

### W1. 스캔 PDF: '이름:' 다음 줄에 쓴 이름을 못 읽고 라벨 낱말 '이름'을 이름으로 읽음
- 화면·단계: 자료 Inbox › 하이브리드 OCR 예시 묶음 › 페이지 묶기(10)
- 재현: 더미 학습지 1쪽(머리글 `학번: 10399` / `이름:` 다음 줄 `가나다`) → '읽은 값: 10399 이름'. 2쪽(`이름: 가나다` 한 줄)은 맞게 읽음.
- 원인: `app/scan.py` `extract_ids` — 라벨 규칙(`RE_NAME_LABEL`)이 줄을 넘지 않아 못 찾고, 마지막 규칙 '학번 바로 뒤의 한글 2~4자'가 다음 줄의 라벨 낱말 `이름`을 잡음.
- 영향: 학생 매칭에서 '이름 다름' 추천으로 떨어지거나 잘못 짝지어질 수 있음(학번이 맞으면 학번으로 찾음). 손글씨 학습지에서 흔한 모양.
- 캡처: `e2e/s10_pages.png`

### W2. 프롬프트 마법사 Chat: [보내기] 버튼이 처음에 안 보임(125% 배율 노트북)
- 화면: 프롬프트 › 프롬프트 마법사 › 💬 Chat (6)
- 재현: 1920×1080·125%(앱 안 1536×794)에서 열면 [보내기]가 스크롤 칸(`.cw-body`) 아래에 잘려 있음(보내기 아래 끝 723px, 보이는 칸 아래 끝 683px). 칸 안을 스크롤해야 보임.
- 캡처: `e2e/s06_wiz_chat.png`

### W3. 태그별 기록: 고쳐 저장한 뒤 [AI 변환] 확인 창 '대상' 바이트가 옛 값

- 재현: 원문에 글을 더해 Ctrl+S(93 → 108 Byte) → [AI 변환] → '대상 … (93 Byte)'. 화면을 다시 그리면 108로 맞음.
- 원인: `app/web/app.js` `tvAiRecord`·`tvWizCtx`가 처음 불러온 `r.orig`를 씀. AI 호출 자체는 서버의 저장된 글을 써서 결과는 맞음(확인함). 단, 같은 `r.orig`를 쓰는 [프롬프트 마법사]에는 옛 글이 들어갈 수 있음(화면으로는 확인 안 함).
- 캡처: `e2e/s04_tag.png` 뒤 확인 창(따로 캡처 안 함)

### W4. 자료 Inbox '이미 보낸 행' 표: '원본 위치' 머리가 한 글자씩 세로로 꺾임

## 확인 못 한 것과 이유
- 배포 exe의 로딩 창(글꼴·문구·막대): 다시 실행할 때 너무 빨리 지나가 캡처하지 못함.
- 배포 exe의 첫 실행 마법사: 가짜 자료를 미리 넣어 켜서 보지 않음.
- [xlsx 저장]·[꾸러미 파일로 저장…] 파일 창: 운영체제 창이라 자동으로 못 누름. 같은 함수(`export.write_xlsx`, `share.build`)로 파일을 만들어 openpyxl·`share_open`으로 확인. 꾸러미 가져오기 화면은 `share_open`에 경로를 넣어 띄워 확인.
- 새 묶음 → [스캔 PDF] 읽는 방식 화면(하이브리드/CLOVA만/Qwen만, 가림 슬라이더, 가림 0% 동의 창): `inbox_scan_pick`이 경로를 받지 않아 사용자가 파일 창에서 골라야 함.
- 직접 만든 예시 이름 파란 글씨: 데모에 직접 만든 예시가 없음.
- [🔍 맞춤법 검사]: 바깥 사이트로 글이 가서 누르지 않음(규칙).
- AI '기록 제목을 넣어 시작'이 실제 결과에 반영되는지: 가짜 AI라 확인 불가(체크 칸만 확인).
