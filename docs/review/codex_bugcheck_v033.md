### B1. 꾸러미로 예시를 여러 개 가져오면 ID가 겹쳐, 하나를 삭제할 때 다른 예시까지 함께 지워짐

- 위치: `app/examples.py:84`, `app/examples.py:88`, `app/examples.py:93`, `app/share.py:277`.
- 재현: 예시 메뉴에서 기존 예시를 모두 지운 상태로, 서로 다른 예시 20개가 든 꾸러미를 모두 ‘새 이름으로 추가’하여 가져옵니다. 이어 가져온 예시 하나를 삭제합니다.
- 결과 / 기대: 시계를 조작하지 않은 로컬 재현에서 20행의 ID가 **16종류뿐**이었습니다. ‘예시 1’과 ‘예시 2’가 같은 ID를 가졌고, 그 ID로 한 번 삭제하자 **2행이 함께 삭제**됐습니다. 각 예시는 고유 ID를 가져야 하고 삭제는 선택한 한 개에만 적용되어야 합니다.
- 원인: 새 ID를 `my_{int(time.time() * 1000)}`로만 만듭니다. 빠른 연속 저장에서는 같은 밀리초에 두 항목이 생성될 수 있습니다. 저장 뒤 반환도 같은 ID의 첫 항목을 고르고, 수정은 첫 항목만, 삭제는 같은 ID의 모든 항목을 대상으로 합니다.
- 고칠 방향: UUID 등 충돌하지 않는 ID를 쓰고 기존 중복 ID의 복구 방식을 마련합니다. 빈 예시 목록에 꾸러미 여러 개를 연속 추가한 뒤 각각 수정·삭제하는 시험을 넣습니다.

### B2. 60자짜리 이름이 겹치는 프롬프트를 ‘새 이름으로 추가’하면 가져오기가 끝나지 않음

- 위치: `app/share.py:207`, `app/share.py:210`, `app/share.py:252`; 호출 `app/api.py:1434`.
- 재현: 이름이 정확히 60자인 프롬프트를 만들고 꾸러미로 저장합니다. 같은 프롬프트가 있는 상태에서 그 파일을 열어 ‘새 이름으로 추가’합니다.
- 결과 / 기대: `share_import`가 반환하지 않습니다. 재현은 0.3초 뒤 임시 타이머로 중단했습니다. 코드를 보면 반복마다 이름이 동일하므로 시간을 더 줘도 종료되지 않습니다. 기대는 기존 항목을 남기고 구분되는 이름으로 한 개 추가하는 것입니다.
- 원인: `_new_name`이 원래 이름 뒤에 접미사·번호를 붙인 다음 **전체를 앞 60자로 자릅니다**. 원래 이름이 이미 60자이면 접미사와 증가하는 번호가 모두 사라져 `while n in taken`에서 벗어날 수 없습니다. 같은 함수를 쓰는 명시적 이름의 예시에도 영향을 줄 수 있습니다.
- 고칠 방향: 접미사·번호가 들어갈 길이를 먼저 확보하여 본래 이름을 자르고, 시도마다 실제로 다른 후보가 만들어지게 합니다.

- 고칠 방향: 이름 정규화·길이 정책과 충돌 검사를 미리보기·적용에서 일치시키고, 실제 대상이 달라지면 다시 확인합니다. 가능하면 기존에 허용한 태그 이름을 가져오면서 임의로 줄이지 않습니다.

- 원인: 확대 목록에 `.conf-text`가 없고, `.tw-prompt`의 클래스 규칙이 더 뒤의 일반 `textarea` 규칙보다 우선합니다. `.exp-text`도 별도의 고정 크기라 내보내기 본문은 커지지 않습니다.
- 확인 방식: 전체 CSS의 선택자·우선순위 추적으로 확인했습니다. 브라우저를 열어 실제 화면을 계측한 결과는 아닙니다.
- 고칠 방향: 본문과 입력 칸의 적용 대상을 정리하고, 구체적인 고정 크기 규칙에도 `--bs`를 일관되게 적용합니다.

## 의심 (확인 필요)

### S1. 학생 화면을 다시 그릴 때 글자 크기 이벤트가 계속 쌓이는 성능 문제

- 위치: 시작 시점 `app/web/app.js:3692`, `app/web/app.js:3696`.
- 근거: `fitFinalTa`를 호출할 때마다 `window`에 익명 `sgb-fs` 리스너를 추가하고 제거하지 않습니다. 학생 전환·재조회로 없어진 textarea도 클로저가 잡고, 글자 크기를 바꿀 때 옛 콜백까지 호출됩니다. `ResizeObserver` 정리도 확인할 필요가 있습니다.
- 확인 필요: 학생을 많이 오간 뒤 메모리·이벤트 처리 시간이 늘어나는지는 브라우저/앱 실측을 하지 않았습니다. 이것을 사용자 체감 장애로 확정하지 않았습니다.
- 방향: 수명 종료 시 리스너·옵저버를 정리합니다. 점검 중 별도 작업본에는 연결이 끊긴 textarea의 리스너를 제거하는 변경이 들어왔지만, 여기서는 그 변경의 성능까지 검증하지 않았습니다.

### S2. 꾸러미의 개인 정보 경고 범위가 일부 항목에 한정됨

- 위치: `app/share.py:68`, `app/share.py:92`, `app/web/app.js:1596`.
- 근거: 명렬 이름·학번 검사는 프롬프트·예시·태그 프롬프트만 대상으로 합니다. 예시의 과목·출처, 어휘·유의어·사전의 사용자 작성 설명 등은 전체 범위로 검사하지 않습니다. 목록 종류 세 개는 경고 결과 없이 처음부터 선택됩니다.
- 확인 필요: 경고의 제품 요구가 모든 사용자 작성 글을 포함하는지 확인이 필요합니다. 코드가 명렬·기록 테이블 자체를 꾸러미에 싣는다는 뜻은 아니며, 점검 중 실제 전송도 없었습니다.
- 방향: 검사 대상 범위를 명확히 적거나 내보내는 문자열 전체에 동일한 검사를 적용합니다. 자동 이름 표시와 별도로 검토할 항목입니다.
