# v1.0 준비도 평가 (v0.33.2)

## 결론

- **조건 충족 후 가능 — 현재 v0.33.2를 그대로 1.0으로 내는 것은 보류합니다.**
- 핵심 작성 흐름은 구현되어 있고, 지난 B1~B9에 대응하는 수정과 회귀 시험도 확인했습니다. 새 대형 기능을 더 만드는 단계보다는 검증·정리 단계에 가깝습니다.
- 다만 꾸러미 가져오기 실패 시 태그 DB의 일부 변경이 남는 문제가 재현됐고, Windows 배포 CI에는 최근 시험 10개 파일이 빠져 있습니다.
- 교사용 실제 작업 검증과 Windows 업데이트·복구 확인이 남았으며, 도움말·요구사항·보안 문구에 현재 동작과 어긋나는 설명이 있습니다.

## 1.0 전에 꼭 할 것 (막는 것)

1. **꾸러미 가져오기 실패 시 설정 파일과 태그 DB를 함께 복구하기.** `app/api.py:1425`의 예외 처리는 설정 JSON만 되돌립니다. 기존 태그의 확정 지침을 바꾼 뒤 다음 태그 쓰기를 실패시키면 첫 지침은 바뀐 채 남습니다. 완료 기준은 정상 파일의 뒤쪽 저장 실패를 주입해도 기존 설정·태그·확정 지침이 모두 그대로이고, 실패한 작업을 다시 실행해도 중복이 생기지 않는 것입니다.
2. **출시 CI에 현재 회귀 시험 전체를 연결하고 실패 시 빌드를 막기.** 현재 47개 중 37개만 명시되어 있습니다. 특히 `test_share.py`가 없어 지난 자료 손실 수정 시험을 배포 시 실행하지 않습니다. 빠진 10개를 포함하고, 앞쪽 Python 시험 하나를 일부러 실패시켰을 때 빌드·Release로 진행하지 않는지 확인해야 합니다. 직접 실행 전용 시험도 빠뜨리면 안 됩니다.
3. **Windows exe와 Mac 소스에서 더미 자료로 핵심 흐름을 완주하기.** 새 사용자 / 담임·비담임 / 새 학년도·보관 학년도 / 빈 자료 / 마감 / 취소·중지·재시도까지 확인합니다. Windows 1366×768·125% 배율, 좁은 가로 창, 세로 화면, 본문 150%에서 저장·확정·마감·삭제 버튼에 접근할 수 있어야 합니다. 마지막은 xlsx·클립보드의 학생 순서·한글·줄바꿈·1·2학기·반별 시트와 실제 입력 대상에서의 붙여넣기까지 확인합니다.
4. **배포본의 업데이트·복구를 확인하기.** 이전 버전 더미 자료 → 업데이트 전 백업 → exe 교체 → 종료 후 재실행 → 자료·스캔·마감 상태 유지, 그리고 백업 복원·복원 되돌리기를 한 번에 확인합니다. 쓰기 권한 부족·내려받기 실패·검증 불일치 때 현재 자료를 유지해야 합니다. exe를 예전 것으로 되돌리는 일과 자료 형식을 복구하는 일을 같은 것으로 안내하지 않아야 합니다.
5. **사용 안내와 보안 설명을 현재 동작에 맞춰 정리하기.** 설정 탭 목록, 예시·어휘·유의어·글자 크기, 제목 넣기, 맞춤법 검사, 반별 시트, 꾸러미·복구 절차를 찾을 수 있어야 합니다. 삭제 위치와 업데이트의 ‘종료 후 다시 시작’ 동작도 맞춰야 합니다. 처음 쓰는 교사가 도움말만 보고 더미 학생 한 명의 최종안 작성·검토·내보내기를 마치는 것으로 확인합니다.
6. **정식 버전의 표시·범위·남은 제한을 확정하기.** VERSION 숫자만 바꾸어도 창·인트로·앱 정보·Release 제목의 ‘베타’가 없어지지는 않습니다. 어떤 기능을 정식 지원하는지, Mac은 소스 실행이라는 점, 평문 저장·AI 결과의 교사 검토·외부 서비스 의존성을 일관되게 적고, HANDOFF의 필수 항목을 실제 확인 결과로 닫은 뒤 출시합니다. 이번에는 관련 파일을 수정하거나 출시 작업을 하지 않았습니다.

## 1.0 뒤로 미뤄도 되는 것

- 앱 아이콘 최종 시안, 로딩 글꼴·문구·막대의 취향 조정, 마법사 창의 정확한 인디고 색감.
- 태그 안내가 꼭 한 줄인지, 작은 메뉴 버튼이 미적으로 답답한지, 단순 괄호 중복 표기. 단, 줄바꿈·겹침 때문에 버튼을 못 누르거나 본문을 못 읽는 경우는 출시 전에 해결해야 합니다.
- 꾸러미 개인정보 검사 범위를 어휘·유의어·사전·예시 출처까지 자동으로 넓히는 일. 현재 제한을 보안 탭에 명시했으므로 확장 자체를 1.0 필수 기능으로 요구할 필요는 없습니다. ‘모든 개인정보를 자동으로 제거한다’고 안내하면 안 됩니다.
- 맞춤법 검사 결과를 앱 안으로 자동 수집하는 기능. 현재 외부 브라우저 방식은 의도된 범위이며, 사용자가 하지 않기로 한 자동 연동을 출시 조건으로 추가할 이유가 없습니다.
- Mac 설치 패키지, 지원하지 않는 과거 운영체제까지의 확대, 새 AI 모델 추가, 고급 시각·성능 계측의 상시 자동화.
- 배포물 코드 서명·종속성 고정 강화·자동 건강 점검 후 롤백 같은 추가 개선은 별도 우선순위로 판단할 수 있습니다. 현재 구조에 이런 기능이 있다는 뜻은 아니며, 이를 새 대형 개발 목록으로 만들어 1.0을 무기한 미룰 필요는 없습니다.

## 영역별 자세한 근거

### 1. 평가 방법과 실제 확인 범위

- 요청서가 지정한 README, HANDOFF, REQUIREMENTS, 지난 버그 점검, `index.html`의 도움말·유의 사항을 읽고 현재 백엔드·화면 코드·Windows workflow·테스트와 대조했습니다. `app/__init__.py`의 VERSION은 `0.33.2`입니다. 브랜치 이름은 요청서 기준이며 git 명령으로 조회·검증하지 않았습니다.
- 현재 `app/`·`tests/`를 로컬 임시 폴더 `/private/tmp/sgb-v1-ready/snapshot`에 복사하여 47개 시험 파일을 별도 프로세스로 실행했습니다. 복사 후 원본 코드·시험 파일의 해시가 바뀌지 않았음을 확인했습니다. 코드 수정은 하지 않았습니다.
- Python 실행은 임시 `SGB_DATA_DIR`, 바이트코드·pytest 캐시 저장 금지, 외부 플러그인 자동 로딩 금지, 소켓·DNS·브라우저 실행 차단을 적용했습니다. 실제 사용자 설정·자료를 읽거나 시험에 쓰지 않았습니다.
- **Chrome뿐 아니라 다른 브라우저와 브라우저 자동화도 실행하지 않았습니다.** 웹·OpenRouter·CLOVA·맞춤법 사이트·텔레그램 요청을 하지 않았고 git 작업도 하지 않았습니다. 이번 요청에서 허용한 이 결과 파일만 저장소에 작성했습니다.
- 따라서 아래 평가는 코드·문서·로컬 시험에 근거합니다. 실제 Windows exe, WebView2 렌더링, 사용자의 학교 망, 원격 Actions/Release 성공 상태를 검증했다는 뜻은 아닙니다. HANDOFF에 적힌 과거 사용자 확인은 그 기록에 따른 근거로 구분했습니다.

`docs/REQUIREMENTS.md`는 2026-11-07~08 결정이 중심이고 서로 다른 시점의 규칙이 함께 있습니다. 예를 들어 F3의 기록당 여러 태그와 현재 한 태그, F5와 D2-21의 상태 색 차이, J11의 기록당 후보 3개와 현재 기록 결과 묶음 보존, J12의 마감 태그 변경 금지와 현재 태그 정리 예외, J15의 옛 일괄 종합이 그러합니다. README의 후속 변경 기록은 이 변경의 이유를 설명하므로, 이를 모두 ‘기능 미구현’으로 세지 않았습니다. **최신 결정 목록과 옛 요구의 대체 관계**를 정리해 1.0의 완료 기준으로 써야 합니다.

C5·J22의 3학년 1학기 마감은 ‘표시만, 자동 마감 없음’이라는 최종 설명까지 함께 봐야 합니다. 자동 마감 기능을 새로 만들어야 한다는 결론은 아닙니다.

### 3. 지난 점검 이후 안정성 — 수정은 확인했으나 원자적 실패 복구가 덜 끝남

| 지난 지적 | 현재 확인 | 판정의 한계 |
| --- | --- | --- |
| B1 예시 ID 충돌 | 새 ID가 UUID이며, `examples.load()`는 이미 겹친 ID도 분리하여 저장함. 임시 중복 예시 2개에서 하나 삭제 후 1개 보존을 확인 | 실제 사용자 폴더는 열지 않음 |

| B3 태그 이름 충돌 | 미리보기와 반영이 `_tag_name`을 공유. 긴 이름 시험 통과 | 임의 길이·모든 Unicode 이름을 보장하는 시험은 아님 |
| B4 뒤 항목 실패 시 일부 저장 | 사전 검증과 설정 JSON 복구를 추가. 이전의 빈 사전 재현은 회귀 시험에서 차단 | 아래 태그 DB 실패 주입은 여전히 부분 반영 |

| B6 합치기에서 새 하위 항목 누락 | 유의어 표기·제외어, 유형 설명·추천 유형을 합침. 시험 통과 | 서로 다른 설명의 우선순위는 내 값을 유지하는 정책 |
| B7 유의어 캐시 미갱신 | 꾸러미 가져오기 성공 후 `banLoad()` 호출 | 실제 화면 강조는 미실행 |
| B8 자동 예시 이름 | label 분리, `_ex_label`로 표시·겹침·덮어쓰기 통일. 시험 통과 | 실제 선택창은 미실행 |
| B9 본문 확대 누락 | `.conf-text`, `.tw-prompt`, `.exp-text`에도 `--bs` 적용 | 150%·좁은 창의 겹침은 실화면 확인 필요 |
| S1 이벤트 누적 | 연결이 끊긴 textarea의 글자 크기 리스너를 제거하는 코드가 있음 | 장시간 메모리·옵저버 정리 실측 없음 |

**추가로 재현한 출시 차단 문제: 꾸러미의 태그 DB 복구 누락.**

- 위치: `app/api.py:1425`~`1443`의 `share_import`, `app/share.py:266`의 `apply`, 태그 확정 설정 갱신 `app/share.py:389`.
- 임시 학년도에 ‘처음 태그’의 확정 지침을 ‘원래 확정 지침’으로 두었습니다. 정상 형식 꾸러미에서 이 태그를 덮어쓰고 ‘둘째 태그’를 추가하도록 선택했습니다.
- 두 번째 `Records.add_tag`에서만 `OSError`를 내는 메모리 대역으로 저장 실패를 주입했습니다. 외부 요청·실제 디스크 손상은 만들지 않았습니다.
- API는 `ok=False`를 반환했고 추가했던 프롬프트는 JSON 복구로 사라졌습니다. 하지만 **첫 태그의 지침은 새 값 ‘자료만 사용’으로 바뀐 채 남았습니다.** 첫 태그가 없던 재현에서는 새 태그 자체도 남았습니다.
- 각 태그 DB 트랜잭션이 먼저 커밋되고 예외 복구는 설정 파일만 복사하기 때문입니다. 현재 꾸러미 가져오기 전 백업 JSON에는 이 DB 변경을 복구할 정보가 없습니다. 학생 원문 삭제를 재현한 것은 아니지만, 실패 안내와 달리 확정한 작업 설정이 바뀌는 자료 보존 문제입니다.

**저장·백업·마이그레이션의 기반은 긍정적입니다.** 설정은 임시 파일 후 교체하고, 읽기 실패 상태에서 저장을 막습니다. SQLite 백업 API, 미완성 백업 게시 방지, 복원 준비 폴더·이전 폴더·복원 중 기록·실패 시 되돌림이 있습니다. 자료 형식 16, 이전 형식 더미 파일의 마이그레이션·건수 유지·형식변경전 백업 시험과 엑셀 복구 지문 시험도 있습니다. 관련 근거는 `app/config.py`, `app/backup.py`, `app/db.py`, `app/xlsx_backup.py`와 해당 시험입니다.

다만 **자동 백업의 DB·스캔 복원, 꾸러미의 설정 JSON 복원, 엑셀 전체 자료 복구는 범위가 다릅니다.** 도움말에서 어떤 파일로 무엇을 되돌리는지 구별해야 합니다. 자동 백업이 같은 PC 안에만 있으므로 디스크 고장까지 막아 주는 것도 아닙니다.

### 7. 배포 / 업데이트 — 장치는 있으나 배포본 확인이 남음

- `.github/workflows/build-windows.yml`은 Python 3.12·PyInstaller 빌드, 버전/태그 일치 확인, exe 자체 시험, exe 교체·잠금·남은 파일 정리 시험, Release 첨부·예비 경로 게시를 정의합니다. `packaging/sgb.spec`에는 웹 리소스와 WebView2 백엔드가 포함됩니다.
- 이 자체 시험은 라이브러리·리소스·교체를 확인하며 **교사가 보는 WebView2 화면을 클릭해 완주하는 시험은 아닙니다**. 원격 실행 기록은 외부 접속 금지로 확인하지 않았습니다.
- `updater.download`는 공식 릴리스 주소와 64자리 SHA-256을 요구하고, 예비 경로에도 같은 해시를 적용합니다. 검증값이 없으면 자동 업데이트를 중단합니다. `Api.update_apply`는 백업 후 exe만 교체하고, 학교 환경을 고려해 자동 실행하지 않습니다.
- 파일 교체 중 오류에 대한 복원 코드와 자료 복원 코드가 있으나, 모든 새 버전 장애를 자동 탐지해 실행 파일·DB를 함께 되돌리는 기능이 있는 것은 아닙니다. 출시 전 수동 복구 절차가 실제로 통하는지 확인해야 합니다.
- Mac은 소스 실행이며 자동 업데이트는 Windows frozen exe에 한정됩니다. 지원 범위를 구별해 안내하면 됩니다.
- 1.0 표시를 확정할 때는 `app/main.py`의 창·인트로, `index.html`의 상단·앱 정보, README, workflow의 기본 Release 제목에 박힌 ‘베타’도 함께 검토해야 합니다. VERSION만 바꾸는 일로 정식 버전 준비가 끝나지 않습니다.
